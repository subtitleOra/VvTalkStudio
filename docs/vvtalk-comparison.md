# 原版 VvTalk VSQX 对照

这项验收区分“连续音高正确写入 VSQX”和“从文字生成了相同的朗读语调”。前者可以通过独立解码比较；后者还取决于文字分词、节奏和语调算法，不能以相同输入的导出误差代替验证。

开发时先定位原版程序实际产生的两个 VSQX，再核对对应工程缓存与原版导出模块。七字例句“祝老师节日快乐”的缓存含 728 个原始音高点，可以作为同输入的对照。调用只读的原版 Writer 在独立目录生成结果，没有改动原安装，也没有将其源码复制进本程序。上述原版文件、缓存、录音和本机对照目录不随公开仓库分发。

## 数值方法

独立解码器读取 VSQX4 的 resolution、tempo、preMeasure、part 起点、音符和 PIT/PBS 事件。它按保持型控制器还原绝对 MIDI 音高：`note_key + PIT × PBS / 8192`。时间按 `tick / (BPM × resolution / 60)` 换算，并将工程前置小节与片段偏移分别处理；清音帧和音符间空白不参与有声音高比较。

原版 Writer 使用固定基准音符、8190 比例与整数截断，PBS 在起始 tick 1 生效；本程序使用 8192、四舍五入和依据曲线范围选择的 PBS，并从 tick 0 写入。这些编码选择会造成有限的整数弯音量化差，逐字符的时间几何和原始曲线则应独立保持。对实际原版文件的导入再导出检查，以及同一 728 点曲线交给两套导出器的检查，最大误差均低于 0.074 音分；这属于编码量化范围，不是两个文字语调算法相同的证据。

公开测试 `tests/test_vvtalk_comparison.py` 在临时目录生成简化数值夹具，使用 `tests/helpers/vsqx_decoder.py` 独立解码，并检查 PBS 事件顺序、无声间隔、前置小节、几何、原文件不变及量化容差。这里保留的是本项目独立实现的解码器；它不导入原版 Talker 或 Writer，也不读取私人缓存。测试夹具只是数值回归数据，不冒充新的原版程序运行结果。

## 文字生成的区别

原版七字缓存来自其文本 Talker 的字音、分词及语调规则。该路径不等于从参考录音提取 F0。当前中文生成使用本工作台的声调模板、词语重置、短语下倾和可编辑节奏；日语使用本地读音与重音核，英语使用音素、音节重音和句调规则。默认文字草稿与原版自动语调的形状及节奏有差异，未声称逐点复刻。

需要接近真人朗读时，应使用内容已知的参考录音、可靠时间标注与 Praat F0，再听取目标引擎合成结果。静态 VSQX PIT/PBS 检查说明编码是否保持曲线，不证明声库自然度或宿主已经试听。参数概念可参阅 [VOCALOID 官方参考手册](https://rsc-net.vocaloid.com/assets/pdf_files/bb/VOCALOID_Reference_Manual_ENG.pdf#page=51)。
